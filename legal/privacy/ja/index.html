Izure プライバシーポリシー

制定日: 2026-09-26 ・ 適用開始日: 2026-09-26
ja| en

本プライバシーポリシー（以下「本ポリシー」）は、Izure（いずれ。以下「本アプリ」）における、本アプリ利用者（以下「利用者」）の情報の取り扱いについて定めるものです。本アプリは Sota Sugiyama（ハンドルネーム mon50）が個人として開発・運営しています（以下「当方」）。

本アプリは、利用者が置いた一片の記録（本アプリでは「半券」と呼びます）を端末内に保存し、あとで開き直せるようにするアプリです。題をつける、リンクを開いたときに読む前の短い案内を出す、関係のある半券を選ぶ、といった処理のために、必要な情報を当方のサーバーと AI へ送ります。本ポリシーでは、機能ごとに何をどこへ送るかを、実装にもとづいて記載します。

1. 取得する情報

当方は、本アプリの動作に必要な範囲で次の情報を取り扱います。

1.1 端末内に保存される情報

次の情報は、利用者の端末内の SQLite データベースに保存されます。当方のサーバーには保存されません。

  • 利用者が入力した、または他のアプリから共有した本文そのもの。
  • 本文から取り出した URL と、そのホスト名。あわせて、URL の先のページの書き出し（最大 60 文字）、付いている写真・動画の数、本文を取得できるかどうかの判定、および中身をこちらから見られないリンクであるかどうかの印。
  • 本アプリが本文につけた題・要約・分類。
  • 利用者が半券に書き足した一言（本アプリでは「判」と呼びます）。
  • 本アプリが生成した次のもの: 自分の言葉で置いた半券に添える「続きの種」、リンクを開いたときに表示する読む前の短い案内（何の話か・読むときの見どころ・読んだあとの問い。本アプリでは「しおり」と呼びます）、中身を見られないリンクについて利用者に向ける問い。
  • 半券どうしをまとめた「束」の対応関係と、束の元とのつながりを示す 1 行（有料プラン「Izure Pro」（以下「本プラン」）のみ）。
  • 新しく置いた半券と同じ話として選ばれた、前に置いた半券との対応と、そのつながりを示す 1 行。
  • 利用者が半券に設定した通知の時刻、半券を切った時刻、削除の状態。
  • リンクの半券から元のページを開いた時刻（ひと月の振り返りの「今月やったこと」の表示に用います。どのページかの中身は含みません）。
  • ひと月の振り返りの結果（その月の話の名前と大きさ、選ばれた言葉の番号、問い、その月の言葉からまとめた 1 行）、「自分に聞く」への利用者の答え、および振り返りで「もういい」「やることにする」を押した言葉の印（言葉そのものではなく、戻せない短い印）。

このデータベースには、本アプリ独自の暗号化を適用していません。保護は端末の OS が備えるディスク暗号化に依存します。詳細は §6 をご覧ください。

次の情報は、OS が備える安全な保管領域（iOS の Keychain / Android の Keystore）に保存されます。

  • 表示モード、アクセント色、通知の設定、オンボーディングの完了状態。
  • 「やってみる」（機能を 1 つずつ試す一覧）の表示の選択と、済んだ項目。ひと月の振り返りの案内を押した月、本プランの案内を表示した記録など、画面の表示に用いる状態。
  • 匿名の端末識別子（§1.3）。
  • 課金状態のキャッシュ（有効・無効、満了日、購入した商品の識別子）。
  • 本アプリがサーバーへの接続に用いるアクセストークン。

1.2 機能ごとにサーバーへ送信される情報

本アプリは、次の操作にあたって、インターネットを通じて当方の運用するサーバー（Cloudflare Workers 上のステートレスなエンドポイント）へ情報を送信します。当方のサーバーは、受け取った情報（および §3.2 で取得したページの内容）を OpenAI 社の API（大規模言語モデル）へ渡し、生成された結果を利用者の端末へ返します。当方のサーバーは受け取った内容を保存しません。OpenAI 社における取り扱いは §4.2 に記載します。

無料・本プランのどちらでも行う操作

  • 半券を置く操作（AI に届かずに置いた半券を読み直す場合を含みます）: 利用者が入力した、または他のアプリから共有した本文そのもの、本文から取り出した URL（最大 4 件）、および端末のローカル時刻（タイムゾーンのずれを含みます）。URL があれば、当方のサーバーがその先から題・説明文・本文の冒頭を取得し（§3.2）、題・要約・分類をつける材料にします。
  • 前に置いた半券から同じ話を選ぶ操作（半券を置いた直後に自動で行います）: 新しく置いた半券の題、URL を除いた本文（最大 300 文字）、ページの書き出し、ホスト名、および前に置いた半券（新しい順に最大 30 件）の題と識別子。中身を見られないリンクの半券については、題に利用者が最後に書いた「判」を添えます。
  • リンクの半券を開いて、読む前の短い案内を作る操作: 当該半券の URL、題、置いたときの一言、ページの書き出し。当方のサーバーがその URL の先を取得し（§3.2）、本文のうち最初の 4,000 文字までと題を、置いたときの一言とあわせて OpenAI 社の API へ渡します。本文が得られず題と説明文しか取れなかった場合は、題とページの書き出しだけを渡します。生成された案内に、取得した本文と 20 文字以上続けて同じ部分がある場合は、書き直させるか、その部分を表示しません。できた案内は端末内に保存し、同じ半券では再び作りません。
  • 中身を見られないリンクについて、利用者への問いを選ぶ操作: Instagram・Facebook・Threads・TikTok のリンク、およびログインが必要なページ、取得を断っているページ（§3.3）、取得できなかったページについては、ページの内容を使わず、ホスト名、URL のうちクエリと「#」以降を除いた部分から読み取れる言葉、半券の題（利用者の言葉、またはサービスの名前だけ）、置いたときの一言を OpenAI 社の API へ渡し、利用者に向ける問いを選ばせます。
  • 中身を見られないリンクの題を、利用者の答えからつけ直す操作: いまの題、ホスト名、利用者が書いた答え（「判」）。
  • 自分の言葉で置いた半券に「続きの種」を作る操作: 置いたときの本文（最大 2,000 文字）、利用者が書いた「判」の日付と本文（最大 20 件）、同じころ（前後 7 日）に置いた他の半券の題（最大 8 件）。

本プランの操作

  • 聞いて探す: 利用者が打った問い、および置いた半券（最大 150 件）それぞれの題、置いたときの一言、ページの書き出し、ホスト名、利用者が書いた「判」、置いてからの日数、済んだかどうか、識別子。
  • ひと月の振り返り（本プラン）: その月に利用者が置いたときに書いた言葉（URL を除いた本文）と「判」、その月に置いたリンクの題と読む前の短い案内の「何の話か」（作ってあれば）、それぞれの日付、および端末に先月の振り返りが残っていれば先月の話の名前と大きさ。AI へ渡すのは最大 200 件、1 件あたり最大 160 文字です。やることの半券と見本は送りません。元のページを開いた時刻と「自分に聞く」への答えは送りません。
  • 束のつながりを示す 1 行を作る操作: 束の元の題と置いたときの一言、束に重ねた半券の題と識別子（最大 12 件）。
  • 束に近い記事を外から探す操作: 束の元の題と置いたときの一言、束に重ねた半券の題と URL（最大 12 件）。当方のサーバーは、題と一言を OpenAI 社の Web 検索の機能へ渡して候補を探させます（URL は重複を除くためだけに使い、検索には渡しません）。見つかった候補のページは、開けることを確かめるために当方のサーバーが 1 回だけ取得し（§3.2）、候補の題とホスト名を、束の元の題・一言・重ねた半券の題とあわせて OpenAI 社の API へ渡して、最大 3 件を選ばせます。この操作には 1 か月あたりの回数の上限があります。

サーバーへ送信しないもの: 本アプリは、利用者と AI とのやりとりの履歴、および画像を、サーバーへ送信しません。「書き出す」（本プラン）は端末内で文を作り、OS の共有の機能へ渡すだけで、当方のサーバーへは送信しません。通知の時刻の指定も端末内だけで扱います。

1.3 通信に付随して送信される識別子

§1.2 の通信には、次の情報が付随します。

  • 匿名の端末識別子: 本アプリが初回起動時に生成するランダムな UUID です。氏名・メールアドレス・ストアのアカウント・広告識別子とは結びつきません。短時間に集中した要求の抑制と、回数に上限のある機能（外から探す）の月ごとの回数の管理に用います。当方のサーバー側に残るのは、この値をハッシュ化した 8 文字の文字列だけで、元の値は復元できません。
  • 現在のプラン種別（無料 / 有料）。回数の上限の判定と、本プランの機能を使えるかどうかの判定に用います。
  • 端末の表示言語（日本語 / 英語）。AI が書く言語と、ページを取得するときに宛先サイトへ伝える言語の希望に用います。
  • 要求ごとの ID: 通信 1 回ごとに本アプリが作るランダムな値です。当方のサーバーのログと §1.7 の診断情報が同じ通信のものだと分かるようにするためだけに用います。端末識別子とは別の値で、通信のたびに変わり、利用者とは結びつきません。
  • 本アプリ共通のアクセストークン。当方のサーバーが本アプリからの要求であることを確認するためのもので、利用者ごとに異なる値ではなく、利用者を識別する情報を含みません。

1.4 端末の権限

  • 通知: 利用者が半券に時刻を設定したとき、その時刻に通知するため、通知の権限を求めます。通知はすべて端末内で予約されるローカル通知であり、当方のサーバーから送るプッシュ通知ではありません。通知の本文には、その半券の題が含まれます。通知は本アプリの設定からいつでも停止できます。
  • 写真ライブラリ・カメラ・位置情報・連絡先・マイク・通話履歴: 権限を宣言しておらず、取得しません。本アプリは画像を扱いません。

1.5 他のアプリからの共有（共有シート）

他のアプリの共有メニューから、本アプリへテキストや URL を渡せます（iOS・Android）。このとき本アプリの画面は開かず、渡された文字列は端末内のファイルに一時的に預かられます（iOS では、本アプリと共有メニューの受け口が共同で使う端末内の領域）。預かった内容は、次に本アプリを開いたとき、または本アプリに戻ったときに読み出され、半券として端末内のデータベースに保存されるとともに、§1.2 の「半券を置く操作」としてサーバーへ送信されます。読み出しが終わると、預かりファイルは削除されます。

共有元のアプリが渡す題（Android の EXTRA_SUBJECT）は、本文と重複する場合に本アプリ側で取り除きます。受け取る種別はテキストと URL のみで、画像は受け取りません。

利用者が第三者の投稿やページを共有した場合、その内容が §1.2 および §3.2 の流れで当方のサーバーおよび OpenAI 社へ渡ります。第三者の権利に関わる取り扱いは 利用規約をご確認ください。

1.6 課金・サブスクリプションに関する情報

利用者が本プランを購入する場合、決済そのものは Apple App Store / Google Play が処理します。当方は、購入状態（サブスクリプションの有効・無効、満了日）を管理するため、購入レシート、ストアが発行する購入識別子、および RevenueCat が自動生成する匿名のアプリ内ユーザー ID（氏名等の本人識別情報とは結びつきません）を、処理者である RevenueCat（§4.1 参照）へ送信します。当方および RevenueCat は、利用者のクレジットカード番号その他の決済情報を取得・保持しません。

また、本プランの機能を使うとき、本アプリはこの匿名のアプリ内ユーザー ID を当方のサーバーへ送り、当方のサーバーは RevenueCat に購入状態が有効かどうかを問い合わせます。当方のサーバーは、この ID と問い合わせの結果（有効かどうか）を最長 10 分間メモリ上に保持するだけで、保存しません。

本アプリにログイン機能はなく、購入状態はストアのアカウントに紐づきます。無料トライアルは提供していません。

1.7 失敗したときの診断情報

§1.2 の操作が失敗したとき（サーバーに届かなかった、応答が遅すぎた、途中で切れた、エラーが返った 等）、本アプリは原因を調べるための診断情報を作り、当方のサーバーへ送ります。失敗はサーバーに届かないことが多いため、診断情報はいったん端末内に保存し（最大 50 件。超えた分は古いものから消します）、次にサーバーへの通信が成功したとき、または本アプリを起動したときに送ります。送り終えた分は端末から消します。

診断情報に含まれるのは、次の項目だけです。

  • 失敗した操作の種類（半券を置く、読み直す、読む前の短い案内、聞いて探す、束の 1 行、外から探す、ひと月の振り返り、続きの種 など）
  • 理由の種類（混んでいる、上限に達した、本プランが必要、届かなかった、時間切れ、応答の形が違った、途中で切れた 等の決まった区分）
  • 止まった所（接続 / 応答待ち / 受け取っている途中）と、かかった時間
  • 本アプリの版、OS の種類と版、プラン種別（無料 / 有料）
  • 相手のサイトのドメイン名（例: example.com）。URL のパス・クエリ・「#」以降は含みません
  • 要求ごとの ID（§1.3）

診断情報に含めないもの: 半券の本文・題・一言・「判」、問いや利用者の言葉、URL のうちドメイン名以外の部分、匿名の端末識別子、RevenueCat のアプリ内ユーザー ID。本アプリは、決まった項目以外を送らないよう、送る前に形を確かめ直します。当方のサーバーも受け取るときに同じ確かめをし、それ以外の項目は捨てます。診断情報は利用者と結びつかず、トラッキング（他社のアプリやウェブサイトをまたいだ追跡）にも用いません。

1.8 当方が取得しない情報

  • 氏名、住所、電話番号、生年月日、性別、メールアドレス等の登録情報（本アプリにアカウント機能はありません）。
  • IDFA / Advertising ID 等の広告識別子。
  • 第三者のクラッシュレポートや解析ツール（Firebase / Crashlytics / Google Analytics / Sentry 等）を介した利用状況。本アプリはこれらの SDK を組み込んでいません。失敗したときの診断情報は、§1.7 のとおり当方のサーバーへだけ送ります。
  • 広告 SDK。本アプリに広告はありません。

2. 利用目的と法的根拠

  • §1.2 で送信された情報は、利用者がその操作で求めた結果（題・要約・分類、読む前の短い案内、問い、続きの種、関係のある半券とつながりの 1 行、探した結果、振り返り、外から探した候補）を生成する目的にのみ利用します。
  • §1.3 の識別子と情報は、回数の上限の管理、短時間に集中した要求の抑制、プラン種別の判定、および AI が書く言語の選択にのみ利用します。
  • §1.6 の情報は、購入状態と利用権限の管理にのみ利用します。
  • §1.7 の診断情報と §1.3 の要求ごとの ID は、失敗の原因を調べて直すこと、および失敗が増えたときに当方が気づくことにのみ利用します。
  • 当方は、機械学習モデルの学習・改善、広告配信、第三者へのプロファイル提供、その他の二次利用を一切行いません。

法的根拠（GDPR）: §1.2・§1.3・§1.6 の取り扱いは、利用者が求めたサービスの提供に必要なものであり、契約の履行を法的根拠とします（GDPR Art. 6(1)(b)）。§1.7 の診断情報は、サービスを動く状態に保つという当方の正当な利益を法的根拠とします（GDPR Art. 6(1)(f)）。診断情報は利用者と結びつかない項目だけに限っています。

3.2 当方のサーバーによるページの取得

当方のサーバーは、次の場合に、宛先サイトへ直接アクセスし、ページの題・説明文・本文を取得します。

  • 半券を置いたとき: 置いた本文に含まれる URL（最大 4 件）。本文は冒頭の約 1,200 文字までを使い、題をつける材料として OpenAI 社の API へ渡します。
  • リンクの半券を初めて開いたとき: その半券の URL。読む前の短い案内の材料として、本文のうち最初の 4,000 文字までを OpenAI 社の API へ渡します（§1.2）。
  • 束に近い記事を外から探したとき（本プラン）: Web 検索で見つかった候補のページ（最大 8 件）。開けることと題を確かめるためだけに取得し、本文は OpenAI 社の API へ渡しません。渡すのは題とホスト名だけです。

取得にあたっては、次のとおり扱います。

  • アクセスは利用者の端末からではなく、当方のサーバーから行われます。利用者の IP アドレスは宛先サイトへ渡りません。
  • 取得先が応答しない場合、内容が HTML またはプレーンテキストでない場合、取得は行わずに処理を続けます。
  • 宛先が localhost やプライベート IP アドレス、標準以外のポートである場合、取得を行いません。
  • X（旧 Twitter）については、X が埋め込み用に公開している syndication エンドポイント（取得できない場合は公開の oEmbed エンドポイント）から、投稿の文と、付いている写真・動画の数を取得します。写真・動画そのものは取得しません。YouTube については、公開の oEmbed エンドポイントから題と投稿者名を、動画のページから説明文を取得します。動画そのものは取得しません。
  • Instagram・Facebook・Threads・TikTok のリンクについては、ページも埋め込み用のエンドポイントも取得しません。これらの半券の題は「Instagram の投稿」のようなサービスの名前と、利用者が書いた言葉だけで扱います。
  • 取得したページの内容は、当方のサーバーには保存されません。

3.3 URL の取得にあたって当方のサーバーが名乗る情報と、取得の範囲

§3.2 の取得にあたり、当方のサーバーは、次の名前（HTTP の User-Agent ヘッダ）を宛先サイトへ伝えます。他のサービスのクローラやブラウザの名前を名乗ることはありません。

IzureBot/1.0 (+https://mon50.github.io/izure-legal/)

括弧内の URL は、本アプリの法的情報のページです。宛先サイトの管理者が、どこからの取得かを確かめ、当方へ連絡できるよう添えています。

取得は、次の範囲に限って行います。

  • 利用者の操作を起点とする取得だけを行います。取得するのは、利用者が置いた URL と、利用者が「外から探す」を押したときに見つかった候補のページだけです。
  • 同じ URL を繰り返し取得しに行くことはありません。利用者が置いた URL は、置いたときに 1 回、その半券を初めて開いたときに 1 回取得します。結果は利用者の端末に保持します。一時的に取得できなかった場合に限り、次に開いたときに改めて取得します。外から探した候補のページは、その操作ごとに 1 回だけ取得します。
  • 巡回は行いません。取得したページに含まれるリンクをたどることはありません。
  • 宛先が localhost やプライベート IP アドレス、標準以外のポートである場合は取得しません（§3.2）。

ページを取得する前に、宛先サイトの robots.txt を確認し、IzureBot または * に向けた Disallow の指定に従います。また、取得したページが meta タグまたは X-Robots-Tag ヘッダで noai・noindex・noarchive・none を指定している場合は、そのページの本文と説明文を使いません。どちらの場合も、本アプリは利用者が置いた題と言葉だけで処理を続けます（外から探した候補であれば、その候補を表示しません）。X・YouTube が埋め込み用に公開しているエンドポイント（oEmbed など）はページではないため、この確認の対象にしていません。YouTube の動画のページはこの確認の対象です。

宛先サイトの管理者の方で、当方からの取得をお断りになりたい場合は、§9 の連絡先までお知らせください。当方において当該サイトからの取得を停止します。

ログインの要求、ページの削除、その他の理由でページの内容を取得できなかった場合、当方はその内容を用いずに処理を続けます。リンクの半券であれば、読む前の短い案内の代わりに、利用者に向ける問いを表示します（§1.2）。

5.2 サーバー側

  • 当方のサーバーは、受け取った半券の本文・題・一言・「判」・問い・URL の内容、および Web 検索の結果を保存しません。

  • 短時間に集中した要求を抑えるため、ハッシュ化した識別子ごとの回数カウンタを同じく保持します。こちらは 1 分および 1 日の単位です。

5.3 アプリ内の「すべて削除」の効果

本アプリの設定にある「すべて削除」を実行すると、端末内のデータベースから次のものが行ごと削除されます。削除済みの印を付けて扱いから外す方式ではありません。

  • 半券の本文と、本アプリがつけた題・要約・検索用の文
  • テーマのラベル、URL の参照（ページの書き出し等を含みます）、添付した画像の参照
  • 「判」、読む前の短い案内、問い、「続きの種」、束とつながりの対応関係
  • 元のページを開いた時刻、ひと月の振り返りの結果、「自分に聞く」への答え、振り返りで押した言葉の印

行を削除しただけでは、データベースファイルの未使用領域に本文の並びが残ることがあります。そのため本アプリは、行を削除するときに、その行が使っていた領域を 0 で塗ります。

あわせて、削除のあとにデータベースファイルそのものを書き直し、未使用領域を切り詰めます。この書き直しは、端末の空き容量が足りないなどの理由で失敗することがあります。失敗した場合は、次に削除を行うときに改めて試みます。書き直しが行われなかった場合でも、上記のとおり削除した行の領域は 0 で塗られています。

次のものは「すべて削除」の対象ではありません。

  • 端末内に残る操作の記録（削除および半券の種別変更・完了について、操作の種別、対象の識別子、件数、時刻）。本文・題・要約・テーマのラベル・URL は含みません。
  • OS の安全な保管領域に保存した設定、匿名の端末識別子、課金状態のキャッシュ。匿名の端末識別子は回数の上限の管理（§5.2）に用いるため、残します。ただし、はじめの案内を見終えた印と「やってみる」の進み具合は消え、次に開いたときは最初から表示されます。
  • 共有シートから受け取り、まだ半券にしていない預かりファイル（§5.1）。次に本アプリを開いたときに引き取られ、預かりファイルは空になります。
  • まだ送っていない診断情報（§1.7。本文・題・URL のパス等は含みません）。次にサーバーへ届いたときに送られ、端末から消えます。

また、「すべて削除」を実行すると、本アプリが OS に予約していた通知はすべて取り消されます。

「すべて削除」を実行しても、本プランのサブスクリプションは解約されず、課金も止まりません。解約は各ストアの設定から行います（利用規約 §8）。アンインストールした場合も同じです。

端末内のデータをすべて消去するには、本アプリをアンインストールしてください。当方のサーバーは §5.2 のとおり本文を保持していないため、当方に対する削除の請求は要りません。

6. 安全管理措置

  • 通信の暗号化: 端末と当方のサーバーの間、当方のサーバーと OpenAI 社の間の通信は、HTTPS（TLS）で暗号化します。当方のサーバーと §3.2 の宛先サイトの間の通信は、宛先が HTTPS に対応している場合は HTTPS で行います。
  • 端末内データの保護: 半券と、本アプリが生成したものは端末内の SQLite データベースに保存されます。 本アプリは、このデータベースに独自の暗号化（SQLCipher 等）を適用していません。 保護は、利用者の端末の OS が備えるディスク暗号化（iOS の File Protection / Android の File-Based Encryption）に依存します。そのため、端末のロック画面のパスコードまたは生体認証を有効に設定し、OS を最新の状態に保つことを強く推奨します。
  • 設定・識別子の保護: アクセストークン、匿名の端末識別子、課金状態のキャッシュ、各種設定は、 OS が備える安全な保管領域（iOS の Keychain / Android の Keystore）に保存します。
  • アクセス制御: 当方のサーバーはアクセストークンを必要とし、トークンのない要求は受理しません（HTTP 401 を返します）。本文の大きさにも上限を設けています。
  • 識別子のハッシュ化: サーバー側で保持するカウンタとログの識別子は、 SHA-256 による一方向のハッシュ値であり、元の識別子を復元できません。
  • サーバー側のデータ最小化: 本文を保存しない設計により、サーバー側からの情報流出のリスクを小さくしています。
